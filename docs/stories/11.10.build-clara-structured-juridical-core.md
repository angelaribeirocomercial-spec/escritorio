## Story

**As a** legal operator using Clara inside the banking workspace,  
**I want** Clara to have a structured juridical core for reading, classifying, and deciding on cases,  
**so that** the agent stops behaving like a contextual surface and starts operating as a real legal engine grounded in the existing workspace data.

## Product Intent

This story strengthens what already exists in Clara instead of rebuilding the product.

The goal is to formalize the core juridical workflow into explicit layers:

1. read the case structure
2. classify the dispute type
3. identify the main legal decision
4. surface missing documents and risks
5. route the user to the correct formal output

## Dependencies

- 11.9 Audit-Driven Foundation Hardening

## Acceptance Criteria

1. Clara exposes a central structured analysis flow for client, case, process, and document context.
2. Clara can classify the main banking-law scenario using existing workspace data.
3. Clara can separate:
   - confirmed facts
   - missing documents
   - risks and inconsistencies
   - next recommended legal step
4. Clara can return a decision-oriented output for the main banking niches already present in the product.
5. Clara output remains tied to the existing workspace entities and does not depend on a standalone generic chat flow.
6. Existing draft generation and record persistence continue to work after the structured core is introduced.
7. Story checklist and file list are updated before closing.

## Risk Assessment

### Implementation Risks

- **Primary Risk**: turning the structured core into a duplicate chat surface.
- **Mitigation**: keep the core output action-oriented and bound to real workspace entities.
- **Verification**: review the output shape to ensure it contains decisions, gaps, and next steps instead of generic prose.

### Rollback Plan

1. Remove the structured core layer.
2. Restore the previous Clara service composition.
3. Keep the existing draft and record flows intact.
