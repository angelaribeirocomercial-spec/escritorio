## Story

**As a** legal team member,  
**I want** secure authentication and protected workspace routes,  
**so that** only authorized users can access LexIA Bancaria.

## Acceptance Criteria

1. Supabase Auth is integrated into the app for sign-in and session handling.
2. Protected workspace routes require a valid session before rendering.
3. Unauthenticated users are redirected to the sign-in flow.
4. The route protection pattern is implemented in a reusable server-side guard.
5. The initial auth flow is compatible with later membership and tenant resolution.
6. No UI component accesses auth state through unsafe ad hoc patterns.

## Dev Notes

### Relevant Context

- Supabase Auth is the recommended authentication layer for the MVP. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Tech Stack]
- The architecture defines a protected route pattern through a reusable server-side session guard. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Frontend Architecture]
- The auth flow must authenticate with Supabase, resolve membership and tenant scope, and then allow workspace access. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Backend Architecture]
- Security requirements state that sessions should be managed by Supabase and auth checks should not leak internal details. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Security and Performance]

### File Locations

- Auth helpers: `apps/web/src/lib/auth/`
- Supabase setup: `apps/web/src/lib/supabase/`
- Workspace route guard: `apps/web/src/app/(workspace)/` or `apps/web/src/lib/auth/`

### Technical Constraints

- Route protection should be server-first, not client-only. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Frontend Architecture]
- No direct Supabase access in visual UI components. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Coding Standards]
- Validate auth boundary inputs and error states cleanly. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Error Handling Strategy]

### Testing

- Cover sign-in path success and unauthenticated redirect behavior.
- Cover route guard behavior for protected workspace pages.
- Use the agreed test organization under `apps/web/tests/`. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Testing Strategy]
