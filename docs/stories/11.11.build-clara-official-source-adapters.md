## Story

**As a** legal operator relying on Clara for banking-law work,  
**I want** Clara to query official and public sources through explicit adapters,  
**so that** the agent can support process monitoring and legal research without pretending that external data was consulted when it was not.

## Product Intent

This story adds the integration layer that the audit identified as missing.

It should prepare the product for source-backed legal work through explicit adapters, not by embedding external calls directly in the UI.

## Dependencies

- 11.10 Build Clara Structured Juridical Core

## Acceptance Criteria

1. Clara has internal adapter boundaries for external data sources instead of ad hoc calls from UI components.
2. The architecture clearly separates internal workspace data from external source data.
3. The first adapters are prepared for:
   - CNJ / DataJud
   - Banco Central do Brasil
   - STJ
   - STF
   - Consumidor.gov / Senacon
4. Each adapter returns a structured response that can be stored or logged by Clara.
5. Clara can report when an external source was not consulted or failed.
6. Existing workspace flows continue to work even if an external adapter is unavailable.
7. Story checklist and file list are updated before closing.

## Risk Assessment

### Implementation Risks

- **Primary Risk**: mixing adapter contracts with UI behavior and making the code hard to audit.
- **Mitigation**: keep source access inside server services.
- **Verification**: inspect the call path to ensure the UI only consumes structured outputs.

### Rollback Plan

1. Remove the adapter contracts.
2. Restore the previous Clara-only service flow.
3. Keep the rest of the workspace unchanged.

- [x] Adapter boundary is explicit
