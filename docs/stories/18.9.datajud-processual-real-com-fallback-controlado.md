## Story

**Como** operadora do escritorio bancario,
**quero** consultar metadados processuais pelo DataJud com fallback controlado,
**para que** a Clara e o cockpit do processo consigam ler a fonte oficial sem inventar dados quando a credencial ou o tribunal nao estiverem disponiveis.

## Product Intent

Esta story fecha a primeira integracao oficial real da fase 5 do PRD mestre novo: DataJud como boundary processual controlado.

## Dependencies

- `docs/product/lexia-bancaria/prd-mestre-escritorio-bancario-v2.md`
- `apps/web/src/server/services/datajud/get-datajud-process.ts`
- `apps/web/src/app/api/processos/[numero]/datajud/route.ts`
- `apps/web/src/app/(workspace)/processos/[processId]/page.tsx`

## Acceptance Criteria

1. O sistema expõe `GET /api/processos/:numero/datajud` com contrato estruturado.
2. O adaptador tenta consultar a API oficial do DataJud quando a credencial existir.
3. Quando a credencial nao existir ou a consulta falhar, o retorno continua controlado e auditavel.
4. O cockpit do processo oferece acesso visivel a consulta do DataJud.
5. `npm run lint`, `npm run typecheck` e `npm test` continuam verdes.
