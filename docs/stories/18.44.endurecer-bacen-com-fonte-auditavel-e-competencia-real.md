## Story

**Como** operadora do escritorio bancario,  
**quero** que a comparacao BACEN do caso use fonte auditavel, competencia real e rastreabilidade operacional,  
**para que** o sistema possa sustentar automacao forte sem depender de referencia controlada fixa ou fallback ilustrativo.

## Analyst Diagnosis

O maior gap atual para elevar confianca comercial do sistema nao esta mais no dossie visual nem no workflow operacional. Ele esta na camada de referencia economica:

- a comparacao BACEN atual ainda trabalha com tabela controlada por modalidade
- a consulta oficial existente no projeto cobre `SGS`, `PTAX` e boundary de tarifas, mas nao fecha a aderencia juridica do contrato bancario por modalidade/competencia
- isso limita a confianca automatica de abusividade, estrategia, laudo, peticao e Clara

Conclusao do `@analyst`:

- o proximo slice correto e endurecer o envelope BACEN para que o sistema confie mais no proprio output sem pedir acao manual do operador
- esse endurecimento deve preservar fallback honesto quando a fonte oficial nao cobrir a modalidade

## Acceptance Criteria

1. O caso persiste a modalidade comparavel e a competencia real usada na consulta BACEN.
2. A comparacao economica deixa de depender primariamente de tabela controlada hardcoded quando existir fonte oficial consumivel pelo sistema.
3. O resultado BACEN registra fonte, data-base, handle/serie usada, resumo e evidencias suficientes para auditoria operacional.
4. Quando a fonte oficial nao cobrir a modalidade do contrato, o sistema cai em fallback controlado e explicito, sem fingir certeza forte.
5. A confianca operacional do caso reflete a qualidade da fonte BACEN usada.
6. Laudo, peticao e Clara passam a distinguir `fonte oficial consolidada` de `fallback controlado`.
7. `npm run lint`, `npm run typecheck`, `npm test` e `npm run build` permanecem verdes.
