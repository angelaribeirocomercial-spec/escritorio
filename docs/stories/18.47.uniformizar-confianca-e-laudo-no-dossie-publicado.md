## Story

**Como** operadora do escritorio bancario,  
**quero** ver de forma consistente no dossie publicado o estado de confianca operacional e a saida pericial/laudo,  
**para que** o fluxo live nao pareca incompleto ou dependente de leitura implícita do caso.

## Analyst Diagnosis

Na validacao publicada de `cl-002` o dossie principal abriu corretamente com as abas centrais, mas dois sinais finais de maturidade nao ficaram inequívocos:

- `Confianca operacional` nao apareceu como texto explícito na tela validada
- a camada `Pericial` nao apareceu com esse rótulo inequívoco no dossie live

Isso nao compromete a fundacao do produto, mas reduz a leitura comercial e operacional do que o sistema ja sabe fazer.

Conclusao do `@analyst`:

- o proximo slice correto e uniformizar a apresentacao live desses estados finais
- a entrega deve preservar o comportamento por caso, mas tornar a comunicacao do dossie consistente e evidente

## Acceptance Criteria

1. O dossie publicado exibe `Confianca operacional` ou equivalente explícito de forma consistente quando houver analise do caso.
2. A camada `Laudo`/`Pericial` fica identificavel de forma inequívoca no dossie live.
3. A exposicao visual nao quebra casos com lacuna de analise; nesses casos, o sistema mostra estado honesto.
4. `npm run lint`, `npm run typecheck`, `npm test` e `npm run build` permanecem verdes.
