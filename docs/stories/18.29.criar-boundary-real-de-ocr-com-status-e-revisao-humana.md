## Story

**Como** gestora do escritorio bancario,
**quero** que o sistema tenha um boundary real de OCR para leitura de contratos e documentos,
**para que** a extracao de dados do caso seja controlada, rastreavel e revisavel por humano quando necessario.

## Product Intent

Esta story reconhece que hoje o sistema possui storage e visualizacao documental, mas nao possui um OCR estruturado como boundary explicito.

O objetivo e criar a fronteira de servico, nao apenas um efeito visual na tela.

## Acceptance Criteria

1. O produto passa a ter boundary formal de OCR, separado da simples exibicao de documentos.
2. O documento enviado pode ser lido, classificado e marcado com status de extracao.
3. O sistema deixa claro quando a leitura precisa de revisao humana.
4. O boundary nao quebra o fluxo de armazenamento ja existente.
5. A leitura de OCR fica associada ao caso e ao documento correspondente.
6. `npm run lint`, `npm run typecheck` e `npm test` permanecem verdes.
