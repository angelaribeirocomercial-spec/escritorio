## Story

**Como** gestora do escritorio bancario,
**quero** que o sistema trate `Cliente -> Caso -> Processo -> Dossie Unico` como a sequencia canonica,
**para que** o produto nao fique dividido entre superficies soltas e o caso continue sendo o centro do fluxo juridico bancario.

## Product Intent

Esta story formaliza a base de dominio do novo recorte do `PRD mestre`.

Ela nao cria uma nova aplicacao, nao substitui o layout e nao reabre PRDs antigos. O objetivo e declarar, com rastreabilidade, que o dossie unico do caso e a unidade central de trabalho. Todo o restante precisa orbitar essa unidade.

O recorte precisa preservar:
- o cliente como entrada do fluxo
- o caso como centro operacional
- o processo como acompanhamento pos-distribuicao
- o dossie unico como agregacao das informacoes do caso
- Clara como camada contextual, nao como substituto do caso

## Acceptance Criteria

1. O PRD mestre passa a ter rastreabilidade explicita para a sequencia canonica `Cliente -> Caso -> Processo -> Dossie Unico`.
2. O dossie unico fica descrito como a unidade central de produto para o caso juridico bancario.
3. A leitura do dominio distingue claramente o papel de `Cliente`, `Caso` e `Processo`.
4. Clara aparece como camada contextual do caso, nao como superficie paralela que compete com o dossie.
5. A story nao introduz duplicidade conceitual com CRM, financeiro operacional ou processo pos-distribuicao.
6. `npm run lint`, `npm run typecheck` e `npm test` permanecem verdes.
