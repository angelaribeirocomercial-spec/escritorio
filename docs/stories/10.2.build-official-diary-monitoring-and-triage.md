## Story

**As a** banking-law attorney,  
**I want** an official-diary module linked to judicial processes and banking cases,  
**so that** I can register, triage, and prioritize publications without losing procedural context.

## Acceptance Criteria

1. An authenticated `diario-oficial` module exists in the workspace and is reachable from the main navigation or an equivalent process-centered entry point.
2. The module exposes a list of official-diary publications with at least process, client, bank, publication date, source court, urgency, summary, and required action.
3. Each publication can be linked to an existing judicial process and its banking case.
4. Publications can be filtered by urgency, bank, responsible lawyer, and linked process status.
5. A publication detail or expanded workspace view shows the raw publication context, ADVX banking interpretation, linked process, and suggested operational next step.
6. The module can create or prepare a downstream task action from a publication without breaking the existing `tarefas` experience.
7. Existing `processos`, `casos`, `documentos`, `tarefas`, and `clara` flows continue to work without regression.

- The initial implementation can be mock-based, but the data model must be ready for future ingestion services.

### Testing

- Keep tests inside `apps/web/tests/`.

## Risk Assessment

### Implementation Risks

- **Primary Risk**: publication triage may duplicate deadline/task behavior if linkage rules are unclear.
- **Mitigation**: treat publication as the source event and task as the downstream action artifact.
- **Verification**: review the publication-to-task flow and ensure task ownership remains in the existing `tarefas` module.

### Rollback Plan

1. Remove the new official-diary routes and navigation entry.
2. Remove publication contracts and mocks.
3. Remove any new task bridge introduced specifically for publications.

### Safety Checks

- [ ] Existing task behaviors reviewed before implementation
- [ ] Publication linkage modeled without replacing current task ownership
- [ ] Clara suggestions remain additive, not destructive
