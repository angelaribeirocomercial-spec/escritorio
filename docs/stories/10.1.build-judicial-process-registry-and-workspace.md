## Story

**As a** legal operator handling banking litigation,  
**I want** a dedicated judicial-process module linked to banking cases,  
**so that** I can register, filter, and understand the real procedural layer of each case without losing the ADVX banking context.

## Acceptance Criteria

1. An authenticated `processos` module exists in the workspace and is reachable from the main navigation.
2. The module exposes a useful list of judicial processes linked to existing banking cases and clients.
3. Each process record includes at least case link, client, bank defendant, process number, tribunal, comarca, court, procedural phase, status, thesis, risk, and responsible lawyer.
4. The module supports filtering by bank, thesis, procedural phase, status, and risk.
5. Each listed process links to an individual process workspace that summarizes overview, banking-case context, latest timeline items, linked deadlines, and linked documents.
6. Existing `casos`, `clientes`, `tarefas`, `documentos`, and `clara` flows continue to work without regression.
7. The implementation remains compatible with the current tenant-aware mock foundation and leaves space for future real persistence.

## Risk Assessment

### Implementation Risks

- **Primary Risk**: introducing a new first-class module may fracture the current case-centric navigation if process and case responsibilities overlap.
- **Mitigation**: keep `caso` as the business anchor and make `processo` explicitly subordinate but navigable as its own workspace.
- **Verification**: review navigation, labels, and cross-links between `casos` and `processos` before story closure.

### Rollback Plan

1. Remove the new `processos` routes and navigation entry.
2. Remove the judicial-process contracts and mocks.
3. Restore route smoke tests to the previous footprint.

### Safety Checks

- [ ] Existing `casos` workflows reviewed before implementation
- [ ] New module isolated behind dedicated routes and contracts
- [ ] Cross-links do not break current case detail flows
