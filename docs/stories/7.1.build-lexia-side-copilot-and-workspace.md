## Story

**As a** legal team member,  
**I want** a persistent LexIA copilot and a dedicated AI workspace with contextual responses,  
**so that** the product demonstrates its core differentiation beyond generic chat.

## Acceptance Criteria

1. The workspace shell includes a persistent LexIA side copilot that adapts its content to the active route context.
2. The LexIA dedicated page shows the four operating modes with premium simulated responses tied to the existing CRM, case, document, task, and dashboard contexts.
3. The LexIA experience explains its contextual basis and surfaces recommended next actions.
4. The implementation remains aligned with the tenant-aware workspace foundation and existing product architecture.

## Dev Notes

### Relevant Context

- LexIA must behave as a contextual intelligence layer, not a generic legal chat. [Source: docs/product/lexia-bancaria/lexia-context-architecture.md#Overview]
- The MVP requires a fixed side copilot and a dedicated AI workspace. [Source: docs/product/lexia-bancaria/backlog-handoff.md#Epic 7. LexIA Contextual MVP]
- Every LexIA response should explain its context, present a main conclusion first, and recommend next actions. [Source: docs/product/lexia-bancaria/lexia-context-architecture.md#Response Design Rules]

### File Locations

- Shell components: `apps/web/src/components/layout/`
- LexIA route: `apps/web/src/app/(workspace)/lexia/`
- Server composition: `apps/web/src/server/services/lexia/`
- Shared mocks: `packages/mocks`

### Technical Constraints

- Keep the side copilot useful without becoming visually noisy.
- Reuse the current mock domain instead of creating disconnected AI examples.
- Keep the response language premium, contextual, and legally cautious.

### Testing

- Verify the LexIA page and server service exist.
- Keep tests inside `apps/web/tests/`.
