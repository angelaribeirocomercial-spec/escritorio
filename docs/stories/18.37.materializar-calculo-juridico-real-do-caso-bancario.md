## Story

**Como** operadora do escritorio bancario,
**quero** que os calculos do caso sejam gerados a partir da extracao persistida do contrato,
**para que** a aba `Calculos` reflita memoria juridica real e nao fallback estatico.

## Product Intent

O addendum do dossie unico exige que o financeiro juridico do caso contenha, quando aplicavel:

1. tabela Price
2. SAC
3. saldo devedor original e revisado
4. diferenca apurada
5. repeticao de indebito
6. liquidacao antecipada
7. outros cenarios do nicho bancario

Esta story fecha o segundo elo da cadeia automatica.

## Acceptance Criteria

1. O caso gera memoria de calculo juridico a partir dos dados persistidos do contrato e do nicho bancario selecionado.
2. A aba `Calculos` deixa claro os dados de entrada, a metodologia usada e o resultado calculado.
3. O sistema registra cenarios relevantes para revisional bancaria, incluindo saldo revisado, diferenca apurada e repeticao de indebito quando aplicavel.
4. Quando faltarem dados essenciais, o sistema bloqueia a conclusao do calculo e informa exatamente o que falta.
5. O calculo passa a ser artefato persistido do caso e deixa de depender de fallback demo para o fluxo principal.
6. `npm run lint`, `npm run typecheck`, `npm test` e `npm run build` permanecem verdes.
