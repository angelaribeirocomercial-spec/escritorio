## Story

**As a** member of the product team,  
**I want** the LexIA Bancaria workspace scaffolded with the agreed full-stack structure,  
**so that** the team can implement the MVP on a stable and consistent foundation.

## Acceptance Criteria

1. A Next.js 14+ workspace is created following the agreed monorepo application-first structure.
2. The main application is located in `apps/web` and uses App Router, TypeScript, Tailwind CSS, and a base configuration compatible with shadcn/ui.
3. Shared package directories are created for `ui`, `domain`, `mocks`, and `config`.
4. Base project scripts exist for `dev`, `build`, `lint`, `typecheck`, and `test`.
5. A root `.env.example` exists with the core variables required by the MVP architecture.
6. The initial scaffold runs locally without breaking the agreed folder conventions.

## Dev Notes

### Relevant Context

- The MVP must use `Next.js 14+`, `TypeScript`, `Tailwind CSS`, `shadcn/ui`, and an application-first monorepo structure. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Tech Stack]
- The recommended repository structure is:
  - `apps/web`
  - `packages/ui`
  - `packages/domain`
  - `packages/mocks`
  - `packages/config`
  - `supabase/migrations`
  - `supabase/seeds`
  - `supabase/policies`  
  [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Unified Project Structure]
- Root environment variables expected by the architecture are:
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - `SUPABASE_SERVICE_ROLE_KEY`
  - `NEXT_PUBLIC_APP_URL`
  - `OPENAI_API_KEY`
  - `SENTRY_DSN`  
  [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Development Workflow]
- The first recommended story from backlog prioritization is the scaffold of the Next.js workspace. [Source: docs/product/lexia-bancaria/backlog-prioritization.md#Recommended First Stories]

### File Locations

- Main app: `apps/web`
- Shared packages: `packages/*`
- Product docs already available in: `docs/product/lexia-bancaria/`

### Technical Constraints

- Keep the architecture as a modular monolith with one deployable app for the MVP. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Architectural Patterns]
- Do not add public API surface prematurely; keep the scaffold compatible with server-first Next.js patterns. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#API and Application Boundary]

### Testing

- Test organization should live under `apps/web/tests/` with room for `unit`, `integration`, and `e2e`. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Testing Strategy]
- Minimum verification for this story should cover app boot and basic quality scripts. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Development Workflow]
