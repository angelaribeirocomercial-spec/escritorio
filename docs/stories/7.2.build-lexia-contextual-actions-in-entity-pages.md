## Story

**As a** legal user navigating clients, cases, documents, and tasks,  
**I want** contextual LexIA actions directly inside each entity page,  
**so that** I can trigger the right AI-supported action without leaving the workflow.

## Acceptance Criteria

1. Client, case, document, and task detail pages expose contextual LexIA action blocks aligned with the active entity.
2. Each contextual block explains the basis of the suggestion, presents a premium simulated conclusion, and offers next actions.
3. The contextual action experience stays visually consistent with the existing LexIA side copilot and dedicated workspace.
4. The implementation remains compatible with the current tenant-aware app architecture.

## Dev Notes

### Relevant Context

- Contextual actions are a required interaction surface of the LexIA architecture. [Source: docs/product/lexia-bancaria/lexia-context-architecture.md#Interaction Surfaces]
- The UI should expose contextual action before free chat when possible. [Source: docs/product/lexia-bancaria/architect-handoff.md#AI Architecture Guardrails]
- Responses should explain context, lead with conclusion, and offer next actions. [Source: docs/product/lexia-bancaria/lexia-context-architecture.md#Response Design Rules]

### File Locations

- Shared layout/components: `apps/web/src/components/layout/`
- Entity pages: `apps/web/src/app/(workspace)/clientes/[clientId]/`, `casos/[caseId]/`, `documentos/[documentId]/`, `tarefas/[taskId]/`

### Technical Constraints

- Keep the experience useful and compact inside dense operational pages.
- Avoid duplicating large chunks of UI across entity pages.
- Reuse the same premium response language introduced in Epic 7.1.

### Testing

- Keep tests inside `apps/web/tests/`.
