## Story

**As a** logged-in legal team member,  
**I want** a premium authenticated shell with sidebar, header, and visual system foundations,  
**so that** the product feels like a real high-value SaaS from the first interaction.

## Acceptance Criteria

1. An authenticated workspace layout exists with fixed sidebar and top header.
2. The shell includes navigation entries aligned with the MVP module focus.
3. The shell includes a global search trigger placeholder and LexIA side panel placeholder.
4. The visual foundation reflects the premium legal-tech direction with tokens or theme variables for navy, amber, neutrals, and soft gradients.
5. The layout is responsive for desktop and mobile without breaking navigation clarity.
6. The shell structure is ready for later pages such as dashboard, clientes, casos, documentos, tarefas, LexIA, equipe, and configuracoes.

## Dev Notes

### Relevant Context

- UX guardrails require a fixed sidebar, header with global search, and a persistent LexIA panel that does not pollute the screen. [Source: docs/product/lexia-bancaria/architect-handoff.md#UX Architecture Guardrails]
- The MVP shell should focus on these modules:
  - Dashboard
  - Clientes
  - Casos
  - Documentos
  - Tarefas
  - LexIA
  - Equipe
  - Configuracoes  
  [Source: docs/product/lexia-bancaria/architect-handoff.md#Suggested Information Architecture]
- The visual direction must feel premium, elegant, legal-tech, and organized, with navy and amber accents and optional dark mode readiness. [Source: docs/product/lexia-bancaria/project-brief.md#Commercial Narrative]
- The app shell is a dedicated architectural component responsible for layout, sidebar, header, search, and LexIA visual persistence. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Components]

### File Locations

- Layout-related UI should live under `apps/web/src/components/layout/`
- Route shell should live under `apps/web/src/app/(workspace)/`
- Shared design primitives can later move into `packages/ui`

### Technical Constraints

- Use Tailwind CSS and shadcn/ui-compatible structure. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Tech Stack]
- Use Zustand only for UI experience state such as sidebar, theme, LexIA panel, and search dialog. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Frontend Architecture]
- Do not access Supabase directly from UI components. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Coding Standards]

### Testing

- Verify responsive behavior of sidebar and header.
- Add tests or coverage that confirm the shell renders expected MVP navigation points.
- Follow the `apps/web/tests/` organization for unit/integration coverage. [Source: docs/product/lexia-bancaria/fullstack-architecture.md#Testing Strategy]
